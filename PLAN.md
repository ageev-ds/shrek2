# PLAN.md — «Путь Шрека»

Настольная игра-бродилка для проектора: 3 команды бросают кубик, ходят по карте из 9 локаций вокруг болота Шрека и проходят мини-игры за луковицы 🧅.
Результат — portable `.exe` для Windows 11 и папка `assets/` рядом с ним. Весь контент редактируется в JSON и заменой файлов, пересобирать приложение не нужно.

> Статус: **готово**, этапы 1–8 выполнены (2026-09-30). Что получилось на деле — в разделе «Фактическая реализация» в конце.

## 1. Выбор стека и почему

| Вариант | За | Против | Решение |
|---|---|---|---|
| **Electron + electron-builder** | Chromium гарантированно проигрывает H.264 и WebM одинаково на любом ПК. Микрофон через Web Audio работает. Portable-таргет из коробки. Весь опыт прошлой игры («Своя игра: Шрек») уже проверен на вашем ноутбуке | Размер ~90 МБ | ✅ **Берём** |
| Tauri | Лёгкий (~10 МБ) | Видео идёт через системный WebView2: кодеки и автоплей зависят от установленной Windows. Rust-тулчейн. Чтение `assets/` рядом с exe сложнее | ❌ |
| Neutralino | Лёгкий | Та же зависимость от WebView2, слабая экосистема | ❌ |

- **Фронтенд:** React 18 + TypeScript + Vite. Архитектура сторов, IPC и сборки та же, что в прошлой игре.
- **Анимации:** Framer Motion только для переходов экранов и «событийных» анимаций: кубик, прыжки фишки, появление карточек. Всё зацикленное (пульсация, частицы, мерцание) — на чистом CSS `@keyframes` и только `transform`/`opacity`.
- **Стили:** обычный CSS с токенами (как в прошлой игре), без Tailwind. Tailwind добавляет сборочный шаг, но не ускоряет рантайм. Готовые «деревянные» стили переносятся из прошлого проекта.
- **Состояние:** Zustand.
- **Звук:** синтез SFX через Web Audio (из прошлой игры). Если в `assets/audio/sfx/` лежит файл с тем же именем, играет он. Проигрывание через `<audio>`/Web Audio, без Howler: меньше кода.
- **Шрифты:** Lobster для заголовков (сказочный, с кириллицей) и Open Sans для текста. Оба вшиты через `@fontsource`.
- **Сборка:** electron-builder, target `portable` x64, `npm run build:portable`.

## 2. Производительность — главный урок прошлой игры

Прошлая игра тратила ~1,2 ГБ ОЗУ и грузила GPU. Причины и что меняю:

| Было | Стало |
|---|---|
| `filter: blur()` на фоне и при переходах экранов, `backdrop-filter` в модалках | Никаких blur-фильтров. Затемнение делается полупрозрачным слоем, переходы — `opacity` + `transform` |
| SVG `feTurbulence` (текстура дерева и шум) на весь экран с `mix-blend-mode` | Текстуры — лёгкие CSS-градиенты. Шумового оверлея нет |
| 26 светлячков как отдельные компоненты Framer Motion (26 JS-анимаций на кадр) | ~12 частиц на CSS `@keyframes`, работают на композиторе и не трогают JS |
| Параллакс на `mousemove` со spring-физикой | Параллакса нет: на проекторе мышь не двигается, а spring-физика расходует кадры |
| Всё смонтировано одновременно | Экраны монтируются по одному. Мини-игры и видео подгружаются лениво (`React.lazy`, `preload="metadata"`) |

Бюджеты из ТЗ, проверяю в автотесте через `app.getAppMetrics()`:
- запуск меньше 5 с;
- переход между экранами меньше 300 мс;
- ОЗУ в простое меньше 500 МБ, при видео меньше 1 ГБ;
- CPU в простое меньше 30%.

Меряю на Linux без GPU (худший случай).

## 3. Где лежит контент

```
Путь-Шрека/                        ← то, что получает пользователь (zip)
├── Шрек-Игра-1.0.0-portable.exe
└── assets/
    ├── config/  game.json  locations.json  questions.json  teams.json
    ├── images/  map/  characters/  ui/
    ├── videos/  (intro.mp4, victory.mp4, location_*.mp4 — все опциональны)
    ├── audio/   music/  sfx/  voice/
    └── README_EDIT.md
```

- **Путь к `assets/`:** в portable-режиме `PORTABLE_EXECUTABLE_DIR/assets`, в распакованной сборке `<папка exe>/assets`, в разработке `./assets`.
- **Первый запуск без `assets/`:** exe создаёт папку сам, копируя встроенные дефолты. Поэтому даже один exe без папки — рабочая игра.
- **Чтение конфигов:** каждый JSON читается с диска. Если файл битый или его нет, берётся встроенный дефолт, а на экране показывается жёлтая плашка «⚠ questions.json: ошибка в строке 12 — использую стандартные вопросы». Игра не падает.
- **Медиа** грузятся по `file://` URL (renderer тоже на `file://`). Так видео получает нативную перемотку и стриминг без своего протокола. Отсутствующая картинка заменяется встроенной SVG-заглушкой. Отсутствующее видео просто пропускается. Отсутствующий звук заменяется синтезом.
- **Редактор** (кнопка «Режим редактирования») пишет изменения обратно в JSON атомарно. Перед первой записью за сессию делается копия `config/*.bak.json`.

## 4. Игровой процесс

- **Карта:** SVG-фон болота (редактируемый `images/map/background.svg`). 9 локаций по координатам в процентах из `locations.json`, соединены тропинкой-кольцом. Старт — указатель «Болото Шрека. Посторонним вход воспрещён».
- **Ход:** активная команда жмёт «Бросить кубик» → CSS-3D кубик крутится ~1,2 с → выпадает N → фишка прыгает по кольцу. Шаг — только по **непройденным** локациям, поэтому команда всегда попадает на новую. Пройденные локации фишка перепрыгивает.
- **Локация:** заставка с названием и описанием задания, опционально видео `location_*.mp4` (пропуск по клику) → «Начать задание» → мини-игра → экран результата («+150 🧅», «+50 без ошибок!») → «Продолжить» → ход следующей команды.
- **Конец:** когда все 9 локаций пройдены → финал (ролик `victory.mp4`, если есть; подиум, конфетти, фанфары, «Играть снова»).
- **Сохранение партии** на каждом ходу в `userData/session.json`. Если ноутбук случайно закрыли, можно продолжить.

## 6. Этапы

1. Скелет и сборка: Electron + Vite + React + TS, поиск `assets/`, копирование дефолтов, `build:portable`.
2. Конфиги: типы, чтение с fallback и предупреждениями, дефолтный контент (вопросы по канону: 4 фильма и спин-оффы).
3. Карта, кубик, фишки, очерёдность, одна мини-игра (Быстрые вопросы) — проход end-to-end.
4. Остальные 8 мини-игр.
5. Видео (интро, заставки, победа), музыка, mute, финал.
6. Редактор: команды, локации, вопросы всех 9 типов, очки, тайминги, пути к медиа → «Сохранить».
7. Полировка, замеры производительности, e2e.
8. Portable-сборка, zip `exe + assets`, README и README_EDIT, обновление этого плана.

## 7. Риски

| Риск | Что делаю |
|---|---|
| Portable-exe при каждом запуске распаковывается во временную папку (~3–8 с) | Сжатие `normal` вместо `maximum` (распаковка быстрее), только русская и английская локали Chromium. Время запуска измерю |
| Микрофон на Windows: разрешение или занятость | Electron разрешает микрофон только этому окну. Если `getUserMedia` не сработал, сразу показывается ручная оценка |
| Нет видеофайлов | Все видео опциональны. В сборку положу короткие сгенерированные ролики-заглушки, если получится собрать их без внешних инструментов, иначе шаг просто пропускается |
| Нет Windows для проверки | Linux-сборка того же кода + e2e + замеры. Финальная проверка на ноутбуке — за вами |

## Фактическая реализация

### Что сделано
- Все этапы 1–8. Стек и архитектура — как в плане: Electron 44, React 18, Vite, Zustand, Framer Motion, CSS-токены.
- 9 мини-игр, карта, кубик, фишки, сохранение партии, финал с подиумом и конфетти, редактор всех конфигов.
- Весь контент — в `assets/` (90 вопросов и заданий, 23 SVG-персонажа и предмета, 9 иконок локаций, фон карты). SVG генерируются из кода: `node scripts/gen-art.mjs`.
- Видео и музыки в комплекте нет: все ролики опциональны и пропускаются, вместо музыки играет встроенная синтезированная мелодия. Сгенерировать ролики-заглушки не из чего (ffmpeg в среде сборки нет), так что этот шаг пропущен, как и предусматривал план.
- Сборка: `npm run build:portable` → `release/Путь-Шрека/` (`Шрек-Игра-1.0.0-portable.exe` 88 МБ + `assets/` + `README.txt`) и `release/Путь-Шрека-1.0.0.zip`. Exe без подписи: при первом запуске Windows SmartScreen попросит «Подробнее → Выполнить в любом случае». Иконка и сведения о версии прописаны в exe.
- `scripts/make-icon.mjs` делает `build/icon.png` и `build/icon.ico` из `build/icon.svg`.
- Документация: `README.md` (запуск и игра, он же `README.txt` в архиве) и `assets/README_EDIT.md` (как менять контент).

### E2E (`tests/e2e.mjs`, Playwright + Electron)
8 проверок, все проходят:
1. первый запуск с пустой папкой создаёт `assets/` из встроенных дефолтов;
2. настройка команд → карта;
3. все 9 локаций подряд: кубик (мышью и пробелом) → заставка → мини-игра → результат; локации не повторяются. «Кричи громче» идёт через фейковый микрофон Chromium, то есть проверяется настоящий путь с анализатором звука;
4. финал: подиум, очки, `session.json` удалён;
5. замер простоя;
6. «Продолжить» восстанавливает прерванную партию после перезапуска;
7. редактор пишет правки в `teams.json` и `questions.json` и делает `*.bak.json`, после перезапуска игра видит новые данные;
8. битый `questions.json`, удалённый `locations.json` и удалённые картинки дают жёлтую плашку («questions.json: ошибка в строке 3, столбец 23 — использую стандартный») и SVG-заглушки. Игра не падает.

Дополнительно вручную проверена упакованная Linux-сборка того же кода (`node scripts/build-portable.mjs --linux`): при запуске без `assets/` папка создаётся рядом с исполняемым файлом из `resources/default-assets`.

### Замеры (Linux, без GPU, Xvfb 1600×900)
| Метрика | Бюджет | Факт |
|---|---|---|
| Запуск до главного меню | < 5 с | 0,63 с (распакованная сборка; portable-exe ещё распаковывается, это только на Windows) |
| Переход между экранами | < 300 мс | анимация 220 мс; клик → готовый экран с карточками команд в тесте 370–400 мс вместе с задержками Playwright |
| ОЗУ в простое | < 500 МБ | 475 МБ до сборки мусора, 452 МБ после (сумма PSS всех процессов) |
| ОЗУ в середине партии | < 1 ГБ | 488 МБ |
| CPU в простое | < 30% | 3–4% |

ОЗУ на Linux меряется как PSS: сумма RSS считает общие библиотеки Chromium в каждом процессе заново и даёт завышенные ~880 МБ. На Windows тест берёт private bytes, как в диспетчере задач.

### Баги, найденные и исправленные на этапе 7
- **Редактор падал на вкладке «Команды»**: в Chromium 152 (Electron 44) `window.scrollTo()` возвращает Promise, а эффект `useEffect(() => window.scrollTo(0, 0))` отдавал его React как функцию очистки → `TypeError: c is not a function` и белый экран. Все однострочные эффекты переписаны с фигурными скобками.
- **Фишка кружила по карте десятки прыжков** в конце партии: шаги считаются только по непройденным локациям, и при 1–2 оставшихся бросок «6» давал до 50 прыжков (~20 с). Теперь фишка проходит не больше одного круга: шаги = `(бросок − 1) mod оставшиеся + 1`. Попадание на непройденную локацию по-прежнему гарантировано.
- Предупреждение об отсутствующем `locations.json` показывалось дважды, а сообщение о битом JSON содержало английский текст V8 и не помещалось на экран. Теперь выводится одна строка: «ошибка в строке N, столбец M». Плашка больше не уезжает вправо (её `transform` перебивала анимация появления).

### Что осталось проверить на Windows-ноутбуке
- Время первого запуска portable-exe (распаковка во временную папку).
- Микрофон в «Кричи громче» на реальном железе.
- Синтез речи Windows для «▶ Пример» в «Повтори фразу» (нужен установленный русский голос; без него Windows прочитает фразу голосом по умолчанию или промолчит. Надёжный вариант — положить свою запись в `audio/voice/`).
